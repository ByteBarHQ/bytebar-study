Microsoft Azure Fundamentals (AZ-900) Domain 1.0: Describe Cloud Concepts — Explained

Domain 1.0 is the foundation the whole AZ-900 stands on: what cloud computing is, why businesses adopt it, how costs shift from CapEx to OpEx, and the deployment models Azure offers. Pure concept — learn it once, use it everywhere.

Exam weight: 25–30% · Free study preview from ByteBar

Cloud computing, defined

Cloud computing is the on-demand delivery of computing resources — servers, storage, databases, networking, software — over the internet, with pay-as-you-go pricing.

  • On-demand self-service — provision what you need, when you need it, without human interaction with the provider.
  • Elasticity — scale out automatically as demand rises, scale in when it falls. You stop paying for idle peak capacity.
  • Measured service / pay-as-you-go — metering makes costs track usage. Turn it off, stop paying.
  • Global reach — deploy to Azure regions worldwide, placing resources near your users for latency and compliance.
  • High availability baked in — availability zones (separate data centers within a region) protect against facility-level failure.

CapEx vs. OpEx: the money shift

  • CapEx (capital expenditure) — buying assets upfront: servers, racks, data-center build-out. Big initial spend, then depreciation. The on-premises model.
  • OpEx (operational expenditure) — paying for services as consumed: this month's VM hours, this month's storage. The cloud model.
  • Why it matters — OpEx removes the upfront barrier (startups can start), converts fixed costs to variable ones, and shifts financial risk from "did we buy the right size?" to "are we using what we pay for?"
  • Consumption-based model — you pay for what you use, like electricity. No usage, no bill (for metered services).
Exam phrasing: "a company wants to avoid large upfront costs" → OpEx → cloud. "A company wants predictable costs for stable workloads" → reserved capacity, still OpEx, just committed.

Deployment models and cloud types

  • Public cloud — shared infrastructure owned by the provider (Azure). Cheapest, most elastic, least direct control.
  • Private cloud — dedicated infrastructure for one organization (on-premises or hosted). Most control, highest cost, least elasticity.
  • Hybrid cloud — public + private working together. Keep sensitive workloads private, burst elastic ones public. Azure Arc extends Azure management to hybrid resources.
  • Service models — IaaS (rent VMs — you manage the OS), PaaS (rent a platform — provider manages the OS), SaaS (rent software — provider manages everything).
  • Shared responsibility — Microsoft secures the physical hosts, network, and hypervisor; you secure your data, identities, and configurations. The customer always owns their data and access.

Try it: 4 sample questions

Sample questions to check your understanding of this domain. Answers and full reasoning are tucked under each one.

1. A startup wants to launch an app without buying any servers, paying only for what the app actually uses. Which model fits?

  1. A. A. CapEx — purchase infrastructure upfront
  2. B. B. OpEx — consumption-based cloud spending
  3. C. C. Private cloud — dedicated hardware
  4. D. D. Capital leasing — finance the servers
Show answer & reasoning

B. No upfront hardware plus pay-for-use is the OpEx/consumption model — the cloud's core financial pitch. CapEx (A) and leasing (D) both involve acquiring assets; private cloud (C) is still dedicated infrastructure with upfront cost.

2. A hospital must keep patient records in its own data center but run analytics on Azure. Which deployment model is this?

  1. A. A. Public cloud
  2. B. B. Private cloud
  3. C. C. Hybrid cloud
  4. D. D. Multi-cloud
Show answer & reasoning

C. On-premises systems plus Azure, working together, is hybrid by definition — often driven by regulation, latency, or legacy constraints. Azure Arc is Microsoft's hybrid-management story. Multi-cloud (D) would mean multiple public providers, which isn't described here.

3. A startup's web app idles overnight but spikes every weekday at noon. Under a consumption-based model, what happens to their cloud bill?

  1. A. A. It stays flat — they pay the same every month
  2. B. B. It tracks actual usage: near-zero overnight, higher at the noon spike — they pay for what they consume
  3. C. C. They must prepay a year of peak capacity
  4. D. D. Spikes are free; only baseline usage is metered
Show answer & reasoning

B. Consumption-based = metered like a utility: the bill follows real usage up and down. Idle resources cost ~nothing; the noon spike costs more — and scaling back down stops the meter. Flat fees (A) and upfront commitments (C) are the opposite pattern (commitments can discount consumption pricing, but the metering underneath stays).

4. Under the shared responsibility model, who is responsible for the physical security of Azure data centers?

  1. A. A. The customer — always
  2. B. B. Microsoft — physical hosts and facilities are the provider's responsibility
  3. C. C. Both equally
  4. D. D. The customer's ISP
Show answer & reasoning

B. Physical security of data centers, hosts, and the hypervisor is Microsoft's side of the line — always. The customer owns what's in the cloud: data, identities, configurations. "Who secures the building?" → the provider, on every cloud exam.
