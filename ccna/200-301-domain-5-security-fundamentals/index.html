Cisco CCNA (200-301) Domain 5.0: Security Fundamentals — Explained

Domain 5.0 is security at the network layer: the concepts every secure network assumes (CIA, AAA), hardening the devices themselves, filtering traffic with ACLs, and closing the Layer 2 holes attackers love.

Exam: 200-301 · weight ~15% · Free study preview from ByteBar

Concepts: CIA and AAA

  • CIA triad — Confidentiality (only authorized eyes: encryption, access control), Integrity (data unaltered: hashes, signatures), Availability (there when needed: redundancy, DDoS defense). Every security control serves at least one.
  • AAA — Authentication (who are you?), Authorization (what may you do?), Accounting (what did you do?). Three distinct jobs — a login without authorization is a locked door with the key under the mat.
  • RADIUS vs. TACACS+ — both centralize AAA; TACACS+ (Cisco) encrypts the entire exchange and separates auth/authz/accounting — the device-admin choice; RADIUS encrypts only the password and combines auth+authz — the network-access (Wi-Fi/VPN) choice.
  • Threat vocabulary — malware, phishing, spoofing (forged identity), MITM (silent interception), DoS (availability attack). Name the threat to pick the control.

Device hardening: secure the infrastructure itself

  • Access control — SSH only (never Telnet), strong local passwords / enable secret (hashed, not plaintext), privilege levels limiting what each admin can do, login banners (the legal "you are being watched" notice).
  • Password hygiene on devices — service password-encryption obscures plaintext passwords in configs (weak obfuscation, but better than cleartext); enable secret uses real hashing. Neither survives a determined offline attack — they're speed bumps, not vaults.
  • Control plane protection — limit what can talk to the device: management ACLs on VTY lines, disabling unused services (HTTP, CDP where unneeded). A router you can't reach is a router you can't reconfigure — for attackers too.
  • Physical and boot security — console access = game over eventually; password recovery procedures exist for owners, which is exactly why physical access control matters.
Harden in layers: who can reach the device (VTY ACLs, SSH-only) → who can log in (AAA, strong secrets) → what they can do (privilege levels). Every layer assumes the outer one might fail.

ACLs and Layer 2 security

  • ACLs — ordered lists of permit/deny rules evaluated top-down, first match wins, with an implicit deny all at the end. Standard ACLs filter on source IP only (place near the destination); extended ACLs filter on source/destination/protocol/port (place near the source).
  • Placement logic — standard near destination (it's blunt — don't block legitimate traffic upstream); extended near source (it's precise — stop unwanted traffic early). Backwards placement is the classic ACL question.
  • DHCP snooping — the switch learns which ports are trusted (uplinks to the real DHCP server) and drops DHCP offers from untrusted ports — killing rogue-DHCP attacks.
  • Dynamic ARP Inspection (DAI) — validates ARP packets against the DHCP snooping binding table; forged ARP (the MITM setup) gets dropped. DAI depends on DHCP snooping's table.
  • Port security — limits MAC addresses per switch port (and what happens on violation: protect, restrict, shutdown). One port, one device — no rogue switches or MAC flooding.

Try it: 4 sample questions

Sample questions to check your understanding of this domain. Answers and full reasoning are tucked under each one.

1. An admin needs to block Telnet (TCP 23) from a specific subnet to all servers, while allowing everything else. Which ACL type and placement?

  1. A. A. Standard ACL near the destination
  2. B. B. Extended ACL near the source — it can match protocol/port and stop the traffic early
  3. C. C. Extended ACL near the destination
  4. D. D. No ACL — Telnet can't be filtered
Show answer & reasoning

B. Filtering on port (TCP 23) requires an extended ACL (standard sees only source IP), and extended ACLs go near the source so unwanted traffic dies before crossing the network. Standard (A) can't see ports at all.

2. A user plugs a home router into the office network and it starts handing out wrong DHCP addresses. Which feature would have prevented this?

  1. A. A. Port security
  2. B. B. DHCP snooping — drops DHCP server messages from untrusted ports
  3. C. C. DAI
  4. D. D. NAT
Show answer & reasoning

B. DHCP snooping classifies ports: only trusted uplinks may send DHCP offers; the rogue router's offers arrive on an untrusted access port and die. That's exactly the rogue-DHCP scenario. DAI (C) fights ARP spoofing (and needs snooping's table); port security (A) limits MACs, not DHCP roles.

3. Why does TACACS+ suit device administration better than RADIUS?

  1. A. A. It's faster
  2. B. B. It encrypts the entire AAA exchange and separates authentication, authorization, and accounting — fine-grained control over admin sessions
  3. C. C. It doesn't need a server
  4. D. D. RADIUS can't do authentication
Show answer & reasoning

B. TACACS+'s two advantages are exactly the admin use case: full-packet encryption (RADIUS encrypts only the password) and separate auth/authz/accounting (per-command authorization: "this admin may run show commands but not configure"). RADIUS (combined auth+authz) fits network access like Wi-Fi.

4. An ACL ends without an explicit permit or deny. What happens to traffic matching no rule?

  1. A. A. It's permitted — ACLs default to allow
  2. B. B. It's denied — every ACL ends with an implicit deny all
  3. C. C. It's sent to the CPU for review
  4. D. D. The ACL is ignored
Show answer & reasoning

B. The invisible final line of every ACL is deny ip any any. Traffic matching nothing is dropped — which is why a new ACL that "isn't working" usually just needs its permit lines checked: the implicit deny is doing exactly what it always does.
