CompTIA A+ (220-1201) Domain 4.0: Virtualization & Cloud Computing — Explained

Domain 4.0 is the "where does computing actually happen now" domain: virtual machines on hypervisors, containers beside them, and cloud models that rent you each layer. Small domain, high concept density.

Exam: 220-1201 · weight ~12% · Free study preview from ByteBar

Virtualization: one machine, many computers

A hypervisor abstracts hardware so multiple virtual machines can share one physical host, each isolated from the others.

  • Type 1 (bare metal) — the hypervisor is the OS on the hardware (Hyper-V, ESXi). Data-center standard: maximum performance, no host OS in the way.
  • Type 2 (hosted) — the hypervisor runs as an app on a normal OS (VirtualBox, VMware Workstation). Lab and learning standard: convenient, slightly slower.
  • What a VM needs — virtual CPU, virtual RAM, virtual disk, virtual NIC — all carved from the host's real resources. Overcommit them and every VM suffers.
  • Purpose — server consolidation (ten quiet servers become one busy host), sandboxing (malware analysis that can't escape), and snapshots (roll back a VM to before you broke it).

Containers: virtualization's lighter sibling

Containers virtualize the OS, not the hardware: they share the host kernel and package just the app plus its dependencies.

  • VM vs. container — a VM carries a full guest OS (gigabytes, boots in a minute); a container shares the kernel (megabytes, starts in a second). Containers trade some isolation for speed and density.
  • Use case — microservices and consistent deployments: the container that runs on the developer's laptop runs identically in production.
  • Orchestration — tools like Kubernetes schedule containers across hosts, restart the dead ones, and scale the busy ones. Focus on the concept (automated container management), not the YAML.

Cloud models: what you rent and who patches it

  • IaaS — rent raw infrastructure: VMs, storage, networks. You install and patch the OS and apps. Most control, most work.
  • PaaS — rent a platform: the provider handles OS, runtime, and patching; you deploy code. Less control, less work.
  • SaaS — rent finished software over the browser. You manage users and data; the provider manages everything else.
  • Shared responsibility — security is always shared, but the line moves: IaaS leaves you the OS; PaaS leaves you the app and data; SaaS leaves you the data and accounts. "Of the cloud" (provider) vs. "in the cloud" (you).
  • Deployment models — public (shared, cheapest), private (dedicated, most control), hybrid (both, connected), community (shared by similar organizations).
  • Cloud characteristics — on-demand self-service, broad network access, resource pooling, rapid elasticity (scale out in minutes), measured service (pay for what you use).
Elasticity vs. scalability: elasticity is automatic, rapid scaling with demand (cloud-native); scalability is the general ability to grow. The exam treats elasticity as the cloud's signature trait.

Try it: 4 sample questions

Sample questions to check your understanding of this domain. Answers and full reasoning are tucked under each one.

1. A developer needs a place to deploy code without managing servers or patching operating systems. Which cloud model fits?

  1. A. A. IaaS — full control over the OS
  2. B. B. PaaS — the provider manages OS and runtime
  3. C. C. SaaS — rent finished software
  4. D. D. On-premises virtualization
Show answer & reasoning

B. PaaS exists for exactly this: push code, the platform handles the OS, patching, and runtime. IaaS (A) would add OS management — the opposite of the requirement. SaaS (C) is finished apps, not a deployment target for custom code.

2. A company runs malware analysis inside virtual machines that are reverted after each test. Which virtualization feature makes this safe and repeatable?

  1. A. A. Resource pooling
  2. B. B. Snapshots — rolling the VM back to a known-good state
  3. C. C. Measured service
  4. D. D. Container orchestration
Show answer & reasoning

B. Snapshots capture a VM's exact state; reverting wipes whatever the malware did. Combined with VM isolation (the malware can't easily reach the host), this is the standard sandbox pattern. The other options are cloud characteristics or unrelated tooling.

3. Under the shared responsibility model for IaaS, who is responsible for patching the guest operating system?

  1. A. A. The cloud provider — "of the cloud" covers everything
  2. B. B. The customer — the OS is "in the cloud," their responsibility
  3. C. C. Both equally by default
  4. D. D. Nobody — IaaS operating systems patch themselves
Show answer & reasoning

B. In IaaS the provider owns up to the virtualization layer ("of the cloud"); everything above — guest OS, apps, data — is the customer's ("in the cloud"). Forgetting guest-OS patching is one of the most common real-world IaaS mistakes, which is why the exam asks it.

4. A startup's web traffic spikes 10x every Friday evening and drops Sunday night. Which cloud characteristic handles this automatically?

  1. A. A. Resource pooling
  2. B. B. Measured service
  3. C. C. Rapid elasticity
  4. D. D. Broad network access
Show answer & reasoning

C. Rapid elasticity is automatic scaling with demand — spin up Friday, spin down Sunday, no human involved. Measured service (B) is the billing for that scaling; resource pooling (A) is the shared infrastructure underneath. Elasticity is the behavior; the others are the plumbing and the meter.
